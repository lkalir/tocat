# Contributing to tocat

Thank you for considering contributing! Please take a moment to review the
following guidelines before submitting any issues or pull requests.

## Code of Conduct

Be respectful, constructive, and helpful. Focus on the code, maintain clear
communication, and keep discussions productive.

## How to Contribute

### 1. Reporting Bugs & Feature Requests

Before opening a new issue, please search existing issues to ensure it hasn't
already been reported or requested.

- **Bugs:** Include a clear description of the problem, steps to reproduce,
  expected behavior, and your environment (OS, toolchain version, platform).
- **Features:** Explain the proposed changes, why they would be valuable, and
  any relevant context or alternatives considered.

### 2. Preparing a Pull Request

1. **Fork & Clone:** Fork the repository and clone your fork locally.
2. **Branching:** Create a descriptive feature or bugfix branch (e.g.,
   `git checkout -b fix/buffer-overflow` or `feat/cli-parser`).
3. **Build & Test:** Ensure that your changes compile cleanly, meet existing
   formatting standards, and pass all existing test suites.
4. **Keep it Focused:** Try to keep pull requests concise and single-purpose.
   Large, sweeping changes are harder to review and merge quickly.

## AI Usage & Accountability Policy

You are welcome to use AI tools to help draft code, write documentation, or
debug problems. However, all contributions are held to a strict standard of
personal accountability:

1. **Full Ownership:** You are personally responsible for everything you submit.
   "The AI generated it" is not an acceptable explanation for bugs, broken
   logic, security vulnerabilities, or poor documentation.
2. **Mandatory Verification:** Do not submit unverified or raw AI output. Every
   line of code must be tested, understood, and audited by you prior to opening
   a PR.
3. **Licensing & Provenance:** Ensure that any AI-generated content does not
   violate third-party copyrights, proprietary licenses, or open-source terms.

**In short:** Use whatever tools help you work effectively, but ensure you fully
understand, test, and own the final submission.
